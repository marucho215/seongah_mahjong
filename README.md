# 성아 마작 시뮬레이터 (Seong-ah Mahjong Simulator)

작혼(Mahjong Soul)을 참고한 **산마(3인)** 와 **4마(4인)** 규칙의 결정론적 리치 마작 엔진이다. CharacterAI 상대와 함께,
사람 한 명이 둘 수 있는 브라우저 GUI와 터미널 CLI를 제공한다.

구현 범위는 이 저장소의 테스트가 다루는 동작이며, 실제 서비스의 모든 규칙과 옵션을 똑같이 재현한다고 주장하지는 않는다.
인원 수, 패/패산 구성, 점수 합계, 울기(치/북), 국 길이는 `RuleConfig`로 정한다.

버전 1.2.0 ([릴리즈 노트](RELEASE_NOTES.md)). 개발자용 구조와 현재 상태: [HANDOFF.md](HANDOFF.md).

## 지원 기능

| | 산마 | 4마 |
|---|---|---|
| AI끼리 한 게임 전체 (CharacterAI / 단순 AI) | O | O |
| 브라우저 GUI에서 사람(1석) + AI | O | O |
| 터미널 CLI에서 사람 + AI (실행 한 번에 한 국) | O | O |
| AI끼리 둔 대국의 리플레이 JSON (schema v2) | O | O |
| 사람 + AI 대국의 리플레이 JSON | O | O |
| GUI 로비 (대국 방식, 상대, CustomAI, 시드, 리플레이 저장) | O | O |
| 리플레이 뷰어 (저장된 대국을 현재 엔진으로 다시 진행) | O | O |
| GUI 로비의 AI끼리 관전 (끝까지 진행 후 리플레이 뷰어로 자동 재생) | O | O |
| CustomAI 상대 (사용자가 정한 CharacterAI 파라미터) | O | O |

사람이 마주칠 수 있는 모든 선택에 결정 경로가 있다(GUI와 CLI 모두): 타패와 리치, 퐁, 치(4마만 - 엔진이 준 합법 조합 중에서
고르거나 넘긴다), 대명깡, 암깡, 가깡, 북 빼기(산마), 론 / 넘기기(넘기면 실제 규칙처럼 후리텐이 된다), 쯔모 / 거절,
구종구패 유국. AI 좌석은 항상 자동으로 행동한다(쯔모/론 포함).

## 실행

[Node.js](https://nodejs.org/) 20 이상이 필요하다.

```bash
npm install
```

### 서버 실행

GUI(로비, 대국, AI 관전, 리플레이 뷰어, CustomAI)는 모두 서버 하나(`npm run play:gui`)로 돈다. 쓰는 방식에 따라 켜는 법이 다르다.
아래 예시는 Windows PowerShell 기준이다(macOS/Linux 셸이면 `$env:NAME = "값"` 대신 `NAME=값 npm run play:gui`).

**1. 혼자 쓰기 (로컬 모드)**

```powershell
npm run play:gui
```

창에 `Seongah Majak GUI: http://localhost:3000, 엔진 worker N개`가 나오면 브라우저로 http://localhost:3000 을 연다.
입장 절차 없이 바로 로비가 나온다. 리플레이는 `replays/`, CustomAI는 `custom-ai/`에 저장된다(프로젝트 폴더 기준).

**2. 같은 와이파이의 다른 기기(휴대폰 등)에서 쓰기**

서버는 기본으로 모든 네트워크 주소에서 연결을 받는다. 같은 네트워크의 기기에서 `http://<이 PC의 IP>:3000`을 연다
(IP는 PowerShell의 `ipconfig`에서 "IPv4 주소"). 처음 켤 때 Windows 방화벽이 묻으면 "개인 네트워크"만 허용한다.
이때 같은 네트워크의 누구나 로비 하나를 같이 쓰게 되므로, 여러 사람이 쓸 거라면 아래 3번(공개 모드)으로 켜서 사람마다 나눈다.
휴대폰에서는 대국 화면을 가로로 쓴다.

**3. 누구나 들어와서 AI와 대국하게 열기 (공개 모드)**

```powershell
$env:SEONGAH_PUBLIC = "1"
$env:HOST = "127.0.0.1"
npm run play:gui
```

(`npm run play:gui -- --public`도 같다.) 창에 `(공개: 닉네임만 정해 입장)`이 나온다. 처음 온 브라우저는 닉네임만 정하면
들어오고, 사람마다 로비·대국·CustomAI·리플레이를 따로 가진다(아래 "온라인 입장"). 인터넷 주소는 다른 PowerShell 창에서
Tailscale Funnel로 연다.

```powershell
tailscale funnel 3000
```

나온 `https://….ts.net` 주소를 알려 주면 된다. Tailscale 설치, 절전 설정, 업데이트, 문제 해결까지의 단계별 안내는
[docs/ONLINE_HOSTING.md](docs/ONLINE_HOSTING.md)에 있다.

**4. 아는 사람만 들어오게 열기 (비공개 모드, 선택)**

공개 모드 대신 초대 코드를 주고 켜면, 초대 코드를 아는 사람만 입장한다(초대 코드와 닉네임을 묻는다). 나머지는 공개 모드와 같다.
초대 코드는 앞으로 만들 사람끼리 대전의 입장에도 쓸 예정이다.

```powershell
$env:SEONGAH_INVITE_CODE = "길고-맞히기-어려운-코드"
$env:HOST = "127.0.0.1"
npm run play:gui
```

초대 코드는 명령줄로도 줄 수 있다: `npm run play:gui -- --invite-code <코드>`. 초대 코드와 `SEONGAH_PUBLIC`을 함께 주면
초대 코드가 우선한다(비공개). 공개/비공개를 바꿔 켜도 입장 세션은 같은 파일을 쓰므로, 이미 입장한 브라우저는 그대로 들어온다.

**끄기와 다시 켜기**

서버 창에서 `Ctrl + C`. 서버를 끄면 **진행 중이던 대국과 AI 여러 판 관전 결과는 사라진다**(서버 메모리에만 있다). 저장된
리플레이, CustomAI, 공개/비공개 모드의 입장 상태(`server-data/sessions.json`)는 남는다. 코드를 받은 뒤(`git pull`)에는
`npm install` 후 다시 켠다. 화면 파일(`src/gui/public/`의 html/js/css)은 캐시하지 않으므로, 화면만 바뀌었으면 서버를 다시 켜고
브라우저를 새로고침하면 된다.

**환경 변수**

| 변수 | 기본값 | 뜻 |
|---|---|---|
| `PORT` | `3000` | 받을 포트 |
| `HOST` | 모든 주소 | 받을 주소. `127.0.0.1`이면 이 PC(와 터널)에서만 들어올 수 있다 |
| `SEONGAH_PUBLIC` | 없음(로컬 모드) | `1`이면 공개 모드(누구나 닉네임만 정해 입장) |
| `SEONGAH_INVITE_CODE` | 없음 | 초대 코드. 주면 비공개 모드(공개 모드보다 우선) |
| `SEONGAH_MAX_USERS` | `500` | 공개/비공개 모드의 전체 사용자 수 상한. 넘으면 새 입장만 막는다 |
| `SEONGAH_MAX_GAMES` | `8` | 공개/비공개 모드의 서버 전체 동시 대국 수(AI 관전 포함) |
| `SEONGAH_ENGINE_WORKERS` | CPU 수 - 1 (1~4) | 대국/AI 관전/리플레이 재현을 돌리는 엔진 worker 수 |

PowerShell에서 `$env:`로 정한 값은 그 창에서만 유지된다. 창을 새로 열면 다시 정한다.

**명령줄 인자**: `npm run play:gui -- <시드> --save-replays`는 로비 설정 화면의 초기값(시드, 리플레이 저장)만 채운다.
대국 방식은 항상 로비에서 고른다.

**데이터 위치**

| | 로컬 모드 | 공개/비공개 모드 |
|---|---|---|
| 리플레이 | `replays/` | `server-data/users/<사용자 id>/replays/` (사람당 최근 50개) |
| CustomAI | `custom-ai/` | `server-data/users/<사용자 id>/custom-ai/` (사람당 20개) |
| 입장 세션 | 없음 | `server-data/sessions.json` (토큰 해시만) |

`replays/`, `custom-ai/`, `server-data/`는 git에 올라가지 않는다(`.gitignore`).

### 브라우저에서 두기 (GUI)

```bash
npm run play:gui                                   # GUI 서버를 켠 뒤 브라우저에서 로비를 연다
npm run play:gui -- my-seed --save-replays         # 같음. 시드와 리플레이 저장 옵션을 미리 채운다
```

#### 로비에 들어가서 대국 시작하기

1. `npm run play:gui`를 실행하고 출력된 `http://localhost:3000`을 연다(포트를 바꾸려면 `PORT`).
2. 로비가 열린다. **"대국 방식"** 에서 **산마**(3인) 또는 **4마**(4인)를 누른다. 각 줄에는 인원 수, 시작 점수, 치/북 빼기
   유무가 나온다. 대국 방식을 고르는 것만으로는 대국이 시작되지 않는다. 오른쪽 캐릭터 목록은 둘러볼 수는 있지만, 대국 방식을
   고르기 전에는 좌석에 앉힐 수 없다.
3. 같은 화면에 그 모드의 설정이 나온다(설정 화면은 두 모드가 같고 좌석 수만 다르다).
   - **좌석**: 좌석(하가 / 대면 / 상가)을 누르고 캐릭터 카드를 눌러 앉힌다. 같은 캐릭터는 한 좌석에만 앉을 수 있다.
     "무작위로 채우기"는 좌석을 무작위로 채운다.
   - **CustomAI**: 내 AI를 만들기/편집/복제/삭제한다. 저장한 CustomAI는 캐릭터 목록 끝에 나오고 다른 캐릭터처럼 앉힐 수 있다.
   - **옵션**: 시드(비우면 무작위)와 "게임이 끝나면 리플레이 저장".
   - **"대국 방식 바꾸기"** 를 누르면 2번으로 돌아가 다른 모드를 고를 수 있다.
4. **"대국 시작"** 을 누른다. 나는 seat 0에 앉고 게임이 모든 국을 진행한다. 대국 중에는 오른쪽 위의 **"대국 그만두기"** 로
   확인 후 대국을 끝내고 그 모드의 설정 화면으로 돌아갈 수 있다. 그만둔 대국은 리플레이로 저장하지 않는다.
5. 마지막 국이 끝나면 **"최종 결과 보기"** 에서 최종 결과(엔진이 계산한 순위·점수·pt, 종료 사유, 실제 사용한 시드)를 본다.
   여기서:
   - **"같은 설정으로 다시"**: 같은 모드와 상대, 새 시드.
   - **"같은 시드로 다시"**: 완전히 같은 대국을 다시.
   - **"설정 바꾸기"**: 마지막으로 둔 모드의 설정 화면으로, 마지막 선택이 채워진 채로 돌아간다. 거기서 "대국 방식 바꾸기"를
     누르면 대국 방식 선택으로 돌아간다.
   대국 사이에 서버를 다시 켤 필요는 없다.

#### AI끼리 관전

허브의 **"AI끼리 관전"** 에서 산마 또는 4마를 누르면, 모든 좌석(동가/남가/서가[/북가])에 등록 캐릭터나 CustomAI를 앉히는 설정
화면이 나온다(같은 캐릭터는 한 좌석에만). **"관전 시작"** 을 누르면 서버가 엔진 worker에서 한 게임을 끝까지 진행하고(보통 10~30초),
결과를 내 리플레이 폴더에 `watch-<모드>-<시드>-<시각>_game0.json`으로 저장한 뒤 리플레이 뷰어를 자동 재생 상태로 연다.
뷰어의 국 이동, 수순 이동, 슬라이더, 전체 손패, AI 판단 기록을 그대로 쓴다. 대국은 `npm run sim`과 같은 구성으로 만들어지므로
같은 시드와 좌석이면 시뮬레이션과 같은 대국이 나온다. 진행하는 동안은 동시 대국 한 판으로 센다.

**판 수**를 2~20으로 바꾸면 여러 판을 연속으로 돌린다(판 i의 시드는 `<시드>-i`). 관전 설정 화면 위쪽에 진행률(n/N판)과
좌석별 통계(평균 순위, 1위율, 순위 분포, 평균/합계 pt, 평균 점수, 국당 화료율·방총율·리치율)와 판 목록이 나오고, 새로고침해도
이어진다. **취소**하면 지금 도는 판이 끝난 뒤 멈추고 끝난 판의 결과는 남는다. 판마다 리플레이를 남기려면 "각 판 리플레이 저장"을
켠다(기본은 통계만). 결과는 "결과 지우기"로 지운다(저장한 리플레이 파일은 남는다).

로비 화면 상태는 서버가 들고 있으므로, 새로고침하거나 탭을 하나 더 열어도 같은 화면이 나온다. 서버에 이미 진행 중인 대국이
있으면 페이지를 열거나 새로고침할 때 로비 대신 그 대국으로 돌아간다. 그 대국이 끝나고 "설정 바꾸기"를 고르면 로비가 다시
나온다. 명령줄 인자는 설정 화면의 초기값(시드, `--save-replays`)만 채운다. 대국 방식은 항상 로비에서 고른다(`--mode`는 받기는
하지만 대국 방식 선택을 건너뛰지 않는다). 로비에는 리플레이 뷰어 링크("저장된 리플레이 보기")도 있다.

GUI 기능:
- 산마와 4마가 같이 쓰는 4방향 작탁 하나.
- 패를 눌러 타패(리치는 확인창), 모든 결정에 대한 행동 버튼(치 조합은 패 그림으로 보여 준다).
- AI의 타패/울기/리치/화료를 한 수씩 재생하고, 최근 행동을 짧은 목록으로 보여 준다.
- AI 진행 속도 설정(느림 / 보통 / 빠름 / 즉시). 이미 결정된 AI 턴을 보여 주는 속도만 바꾸고 게임 자체는 바꾸지 않는다.
- 자동 플레이 옵션(기본은 모두 꺼짐): 자동 쯔모기리(방금 뽑은 패를 버림, 리치 없음), 치/퐁/대명깡 제안 자동 넘기기,
  론/쯔모 자동 화료. 각 옵션은 그 결정 하나에만 일반 응답 경로로 답하므로, 다른 사람 선택과 똑같이 리플레이에 기록된다.
- 현재 샹텐, 텐파이일 때(리치 여부와 관계없이) 대기패와 아직 보지 못한 장수(공개 정보만 사용, 실제 패산은 보지 않음),
  후리텐 표시.
- 플레이 보조 토글(표시 전용, 이 브라우저에 저장): **샹텐 표시**(기본 켬, "N샹텐 / 텐파이" 문구만 켜고 끈다. 텐파이 대기패와 후리텐 표시는 끄더라도 그대로 보인다)와
  **위험도 표시**(기본 끔). 위험도는 리치한 상대가 있을 때 내 손패마다 `낮음 / 주의 / 높음`을 붙인다. CharacterAI와 같은
  현물/스지 규칙으로, 리치한 상대의 버림패(남이 울어 간 패 포함)만 보고 매긴 상대적인 표시이며 안전을 보장하지 않는다.
  두 토글 모두 응답, 게임 결과, AI 판단, 리플레이에 영향이 없다.
- 효과음, 결과 화면, 브라우저 새로고침/재접속 때 세션 복구. 리플레이를 저장한 대국은 최종 결과 화면에 "이 대국 리플레이 보기" 링크가 있다.
- 휴대폰: 대국 화면은 가로로 쓴다(세로면 돌려 달라는 안내가 나온다). 좁은 화면에서는 오른쪽 위 조작들이 "메뉴" 버튼 하나로 접힌다.
  로비와 리플레이 뷰어는 세로로도 쓸 수 있다.
- 패 그림 출처: `src/gui/public/assets/mahjong/ATTRIBUTION.md`.

#### 온라인 입장 (공개 / 비공개)

공개 모드나 비공개 모드로 켜면(위 "서버 실행" 3·4번) 입장 게이트가 생긴다. 모든 페이지가 먼저 닉네임(12자 이하)을 묻고
(비공개 모드면 초대 코드도), 입장한 브라우저만 로비, 대국, 리플레이, CustomAI를 쓸 수 있다. 계정이나 비밀번호는 없다. 서버는
브라우저마다 세션 쿠키를 주고(`server-data/sessions.json`에 해시로 저장하므로 서버를 다시 켜도 유지된다), 같은 브라우저로 다시
입장하면 닉네임만 바뀐다. 둘 다 아니면 서버는 입장 없이 동작한다(로컬 모드).

공개 모드는 쿠키를 지워 가며 사용자를 늘리는 남용을 막으려고 새 입장을 제한한다: 서버 전체 한 시간에 60명, 원래 접속지를 알 수
있으면 접속지별 한 시간에 10명, 전체 사용자 수 500명(`SEONGAH_MAX_USERS`). 이미 입장한 브라우저는 제한과 상관없이 들어온다.
Tailscale Funnel 뒤에서는 원래 접속지가 서버에 전달되지 않을 수 있는데, 그러면 접속지별 제한은 건너뛰고 서버 전체 제한만 적용한다.
비공개 모드는 초대 코드를 틀린 시도를 접속지별로 제한한다.

입장한 사람마다 로비, 대국, 이벤트 스트림, AI 속도 설정, CustomAI, 저장된 리플레이를 따로 가진다(같은 브라우저의 여러 탭은
같은 것을 본다). 사용자별 데이터는 `server-data/users/<사용자 id>/custom-ai`와 `.../replays`에 있고, 로컬 모드의 `custom-ai/`와
`replays/` 폴더는 공개/비공개 서버에서 쓰지 않는다. 대국과 리플레이 재현은 엔진 worker 스레드에서 돌아가므로, 한 사람의 AI 턴이나
리플레이 때문에 다른 사람이 멈추지 않는다.

공개/비공개 서버는 자원도 제한한다.
- 서버 전체 동시 대국 최대 8판(`SEONGAH_MAX_GAMES`).
- 30분 동안 요청이 없는 대국은 정리한다(리플레이로 저장하지 않고, 로비에 안내가 나온다).
- 한 사람당 CustomAI 20개, 리플레이는 최근 50개, 동시에 여는 탭 5개, 요청 빈도 제한.

리플레이 뷰어에는 원본 리플레이 파일을 받는 "파일 내려받기" 링크가 있다(버그 제보에 쓴다). 한 대국에는 사람 1명과 AI만 앉는다
(사람끼리 대전은 이후 과제, `HANDOFF.md` §10). 이벤트 스트림은 25초마다 연결 유지 주석을 보내서, 터널이나 프록시가 조용한
연결을 끊지 않게 한다. 켜는 법과 환경 변수는 위 "서버 실행", 인터넷 호스팅 단계별 안내는 [docs/ONLINE_HOSTING.md](docs/ONLINE_HOSTING.md).

#### 친선전 방

공개/비공개 모드 서버에서는 허브에 **"친선전"** 절이 나온다(로컬 모드에는 없다). 공개 방 목록은 없고, 코드를 아는 사람만 들어온다.

- **방 만들기**: 대국 방식(산마/4마)과 시간 제한(작혼 친선전과 같은 3+5초 / 5+10초 / 5+20초(기본) / 60+0초 / 300+0초)을 골라
  만든다. 6자리 방 코드가 나오고("코드 복사"), 방을 만든 사람(방장)이 동가 자리에 앉는다.
- **코드로 들어가기**: 받은 코드를 넣으면 첫 빈자리에 앉는다(소문자, 공백, 하이픈은 무시한다).
- **좌석**: 방장은 좌석을 눌러 고른 뒤 오른쪽 캐릭터 목록에서 AI를 앉히거나(등록 캐릭터와 방장의 CustomAI), "빈자리로" /
  "내보내기"를 누른다. 방에 있는 모든 사람의 화면이 바로 바뀐다.
- **시작**: 빈자리가 없으면 방장이 "대국 시작"을 누른다. 사람끼리(사람 2명 이상 + AI 자유롭게) 한 작탁에서 둔다.
  - 각자 자기 시점으로 두고, 자기 차례가 아니면 "…의 선택을 기다리는 중"이 보인다. 남의 손패는 오지 않는다.
  - 남이 버린 패에 여러 사람이 반응할 수 있으면(론/퐁/깡/치) **모두에게 동시에** 묻는다. 결과는 작혼과 같은 우선순위(론 > 깡·퐁 > 치)로
    정해지고, 론을 넘기면 후리텐이 된다. 한 사람에게 가능한 선택지는 한 번에 버튼으로 나온다.
  - 국 결과에서 누구든 "다음 국"을 누르면 모두 함께 넘어간다. 대국은 방장만 끝낼 수 있고, 끝내면 모두 방으로 돌아간다.
  - 방에서 시작한 대국이 끝나면 "방으로 돌아가기"로 방에 돌아온다.
  - **시간 제한**: 방에서 고른 대로 한 수마다 기본 시간이 있고, 넘기면 국마다 새로 채워지는 여유 시간을 쓴다(작혼과 같은 방식).
    내 차례에는 손패 위에 "5초 + 여유 20초"처럼 남은 시간이 보인다. 시간이 다 되면 중립 AI(캐릭터 성향 없음)가 그 한 수를 대신 둔다.
  - **자리 비움**: 두 번 연속으로 시간이 다 되었거나, 브라우저를 닫고 10초가 지나면 자리 비움이 되어 차례마다 중립 AI가 바로 대신 둔다
    (다른 사람 화면에는 이름 옆에 "(자리 비움)"). 화면 위의 "복귀"를 누르거나, 다시 접속하거나, 직접 한 수를 두면 돌아온다. 사람이
    모두 자리를 비우면 국 결과에서도 기다리지 않고 넘어간다. 대신 둔 결정도 리플레이에 그대로 남는다.
  - **리플레이**: 친선전 대국이 끝나면 참가한 사람 모두의 리플레이 목록에 저장된다(좌석에 닉네임 표시). 대국 중에는 저장하지 않는다.
  - **같은 멤버로 다시**: 방장은 최종 결과에서 "같은 멤버로 다시"를 눌러 방 좌석 그대로 바로 다음 대국을 시작한다.
- **나가기**: 참가자가 나가면 그 자리는 빈자리가 된다. 방장이 "방 닫기"를 누르면 방이 없어지고 모두 로비로 돌아간다. 30분 동안
  아무 활동이 없는 방도 닫힌다. 한 사람은 방 하나에만 있을 수 있고, 방에 있는 동안에는 혼자 대국/관전을 시작하지 않는다.
- 틀린 코드를 10분 안에 10번 넣으면 한동안 들어갈 수 없다.

## 리플레이

`--save-replays`는 대국 하나당 JSON 파일 하나를 `replays/`에 쓴다(상대 경로는 현재 폴더가 아니라 프로젝트 루트 기준):
`<label>_game<index>.json`. 사람이 둔 대국은 `human-<mode>-<seed>_game0.json`(CLI는 `human-cli-<mode>-<seed>_game0.json`)이다.

기록에 들어 있는 것:
- `meta`: `replaySchemaVersion: 2`, 규칙, 게임 시드, 좌석별 `kind`와 `characterId`.
- `events`: 엔진 자체 로그. 배패, 쯔모, 타패, 울기, 리치, 화료(검증 가능한 점수 계산과 도라 내역), 유국, `game_end`.
- `aiDecisions`: CharacterAI 디버그 항목.
- `finalStandings`: 최종 순위.
- 사람 좌석이 있는 대국: `meta.seats[].kind: "human"`, 그리고 선택 필드 `humanDecisions` 배열(무엇을 물었고, 무엇을 골랐고,
  `events`의 어디에서 일어났는지).

schema v2는 v1에 필드를 더한 것뿐이며, 버전이 없으면 1로 읽으면 된다.

리플레이는 테스트가 쓰는 것과 같은 불변식 검사기(`src/validation/`, `tests/helpers/replayQa.ts`)로 검사한다. GUI 대국은 게임이
끝날 때 한 번 저장한다. 게임 도중 서버 프로세스가 죽으면 끝나지 않은 리플레이는 복구하지 않는다(브라우저 새로고침은 기록을
끊지 않는다).

GUI 서버는 리플레이 뷰어도 제공한다: `http://localhost:3000/replay.html`(시작 화면에서 링크).
- `replays/`의 파일을 나열하고, 고른 대국을 기록된 시드, 규칙, 좌석, 사람 결정으로 현재 엔진에서 다시 진행하면서 모든
  이벤트를 파일과 순서대로 비교한다.
- 하나라도 다르면 "현재 엔진 버전으로 정확히 재현할 수 없는 리플레이"라고만 알리고 더 보여 주지 않는다.
- 같으면 국/수순 단위로 옮겨 다니고, 화료·유국 지점으로 건너뛰고, 그 순간 모든 좌석의 손패·멘츠·북·강을 보고, 각 수 직전에
  기록된 CharacterAI 판단 항목을 볼 수 있다.
- 리플레이 파일은 읽기만 하고 고치지 않는다.

## 테스트

```bash
npx tsc -p . --noEmit            # 타입 검사
npm test                         # 전체 테스트 (vitest run) - 약 8분
npx vitest run tests/humanChi.test.ts     # 파일 하나만
npm run test:e2e                 # 헤드리스 브라우저 GUI 스모크 테스트 (npm test에 포함되지 않음)
```

GUI 스모크 테스트(`e2e/guiSmoke.e2e.ts`)는 핵심 화면 흐름만 확인한다. 로비 → 대국 방식 → 설정 → 시작 → 그만두기, 그리고
게임 종료(새로고침 포함) → "설정 바꾸기" → 대국 방식 선택으로 돌아가기. Playwright용 Chromium이 한 번 필요하다:
`npx playwright install chromium`.

테스트가 다루는 영역:
- 점수와 역, 울기와 깡, 리치/후리텐, 도중 유국과 황패 유국, 국 진행.
- 작혼 규칙 충실도 수정(`tests/ff*.test.ts`), CharacterAI 결정론, 리플레이 형식과 불변식.
- 사람 결정 경로(론, 치, 쯔모, 구종구패, 리치 대기), GUI 세션/서버(새로고침 복구 포함).
- 두 모드에서 사람 + AI 게임 전체.

## 알려진 제한과 이후 과제

- **CustomAI**(1차): 시작 화면에서 CustomAI를 만들기/편집/복제/삭제하고 상대로 앉힐 수 있다.
  - CustomAI는 CharacterAI 공통 파라미터 15개를 사용자가 정한 값(한국어 이름이 붙은 0~100 슬라이더)일 뿐이며, 기존
    CharacterAI가 그대로 판단한다.
  - 캐릭터 전용 메커니즘과 가져오기/내보내기는 포함하지 않는다.
  - 파일은 `custom-ai/`에 AI 하나당 JSON 하나(내부 id가 파일 이름)로 저장된다.
  - CustomAI가 앉은 대국은 그 좌석에 실제로 쓴 프로필을 리플레이 메타데이터에 저장하므로, 나중에 고치거나 지워도 옛 리플레이는
    똑같이 재현된다.
- 캐릭터 음성과 화료 컷인, 추가 연출 옵션은 없다. 예전 엔진 버전으로 기록한 리플레이는 뷰어에서 대개 재현할 수 없다(추측하지
  않고 그렇다고 알린다).
- 긴 리플레이를 뷰어에서 열면 게임 전체를 다시 진행하므로 몇 초 걸린다. `npm run play:gui`는 대국과 리플레이 재현을 엔진 worker
  스레드에서 돌리므로(`SEONGAH_ENGINE_WORKERS`, 기본은 CPU 수 - 1, 1~4개) 진행 중인 대국은 멈추지 않는다.
- 새로고침하면 현재 결정, 국 종료, 게임 종료 화면은 복구하지만, 재생 중이던 AI 턴 장면은 다시 재생하지 않는다.
- **GUI는 PC 브라우저 기준이다. 휴대폰 화면은 아직 지원하지 않는다**(손패가 잘리거나 조작 버튼이 상대 패를 가리는 등
  정상적으로 두기 어렵다). 모바일 대응은 다음 버전 과제다.
